# Meeting Notes / 会议纪要整理

## Overview

本技能用于将杂乱的会议记录、语音转写文本或零散笔记整理为结构化的会议纪要。能够自动提取会议核心要素：议题、讨论要点、决议结论、待办事项及责任人，输出规范格式的会议纪要文档。

## 工作流程

### 第一步：识别输入类型

根据用户输入判断来源类型：

- **语音转写文本**：通常口语化、有"嗯"、"那个"等语气词，可能带有时间戳
- **手动笔记**：可能零散、不连贯，关键词为主
- **已有纪要草稿**：需要润色和补全结构
- **会议邀请/议程**：结合议程整理实际会议内容

### 第二步：提取核心要素

从输入中识别并提取以下六要素：

1. **会议基本信息**：会议主题、时间、地点、参会人员（主持、记录、出席、缺席）
2. **议题列表**：本次会议讨论的所有议题，按顺序排列
3. **讨论要点**：每个议题下的关键讨论内容，去除冗余口语
4. **决议结论**：明确达成的决定、共识，用"决定/同意/确认"等措辞
5. **待办事项**：需要后续跟进的任务，必须包含：任务内容 + 责任人 + 截止时间（如有）
6. **下次会议**：如提及下次会议时间或议题，单独列出

### 第三步：选择输出模板

根据会议类型选择对应模板，详见 `references/templates.md`：

- **通用会议模板**：适用于大多数日常会议
- **周会/例会模板**：适用于周期性团队会议，强调进度跟进
- **评审会议模板**：适用于方案评审、设计评审，强调结论和待办
- **头脑风暴模板**：适用于创意讨论，保留更多想法

### 第四步：生成纪要

按以下规范输出：

- 使用 Markdown 格式
- 待办事项用 `- [ ]` 复选框格式，便于后续跟进
- 责任人姓名加粗，截止时间用 `YYYY-MM-DD` 格式
- 决议事项用 `> ` 引用块突出显示
- 讨论内容精简，保留要点，删除口语化内容

### 第五步：补全与确认

如果输入信息不全，主动询问缺失的关键要素：

- 参会人员不明确时，询问主要参会者
- 待办事项缺少责任人时，明确指出并询问
- 决议不清晰时，标注 `[待确认]` 并提示用户

## 输出格式示例

```markdown
# 会议纪要：[会议主题]

**时间**：YYYY-MM-DD HH:MM
**地点**：[线下地点 / 线上会议平台]
**主持人**：[姓名]
**记录人**：[姓名]
**参会人员**：[姓名1]、[姓名2]、[姓名3]...

---

## 议题一：[议题名称]

### 讨论要点
- 要点1
- 要点2

### 决议
> 决定事项的明确表述

### 待办
- [ ] 任务内容 — **责任人** — 截止 YYYY-MM-DD

---

## 待办事项汇总

| 序号 | 任务 | 责任人 | 截止时间 | 状态 |
|------|------|--------|----------|------|
| 1    | xxx  | 张三   | 2026-08-10 | 待开始 |
```

## 使用建议

- 优先保证待办事项的完整性：任务、责任人、时间三者缺一不可
- 决议要明确，避免"讨论了"、"交流了"这种无结论的表述
- 讨论内容做精简，纪要不是逐字稿
- 若输入为英文会议，输出中文纪要时保留专有名词原文
