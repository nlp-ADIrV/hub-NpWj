# 会议纪要 Skill v1 → v2 优化对比报告

## 优化目标

从 **token 消耗** 与 **执行效率** 两个维度优化会议纪要整理 skill，产出 v2 版本。

## 优化动作

| 优化项 | v1 | v2 |
|--------|----|----|
| 脚本依赖 | format_notes.py 正则提取 | 移除，改用模型语义理解 |
| SKILL.md | 内嵌完整输出示例 | 示例移入 references，保留核心规则 |
| 流程步骤 | 5 步 | 3 步 |
| 加载策略 | 未说明 | 明确"简单场景无需读 templates" |
| 模板文档 | 含重复选用表 | 压缩冗余 |

## 量化对比

### Token 消耗（近似：字符数/3）

| 文件 | v1 | v2 | 降幅 |
|------|-----|-----|------|
| SKILL.md（每次必加载） | 600 | 319 | **-47%** |
| references/templates.md（按需） | 705 | 417 | -41% |
| scripts/format_notes.py | 1570 | 0（移除） | **-100%** |
| **合计** | **2875** | **736** | **-74%** |

### 结构与效率

| 维度 | v1 | v2 |
|------|----|----|
| 文件数 | 3 | 2 |
| SKILL.md 行数 | 108 | 43 |
| 流程步骤 | 5 步 | 3 步 |
| 单次任务工具调用 | 读 skill + 脚本 3 次往返 + 读模板 | 读 skill（简单场景仅此一次） |

## 关键收益

1. **恒定开销下降 47%**：SKILL.md 每次触发必加载，从 600 降到 319 token，高频使用累积显著
2. **工具调用减少 3 次**：移除脚本后省去"写→执行→读"往返，降低延迟
3. **提取精度提升**：模型语义理解能区分"陈述观点"与"分配任务"，优于正则匹配
4. **渐进式加载**：v2 标注按需读模板，简单场景仅加载 319 token
