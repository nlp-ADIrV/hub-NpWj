五、相同之处（共性设计）

  • ✅ Decoder-only + 因果自回归：全部是单向 decoder，无一例外。
  • ✅ RMSNorm：全部采用 RMSNorm 而非 LayerNorm（无均值中心化、参数更省）；部分引入 gated RMSNorm。
  • ✅ SwiGLU / SiLU 门控 FFN：除 Kimi 用 SiTU（SiLU 变体）外，全部 SwiGLU（gate/up/down 三段式）。
  • ✅ RoPE 旋转位置编码：全部基于 RoPE（区别在 partial 比例 / YaRN 长文本 / interleaved 排列）。
  • ✅ MoE 稀疏专家 + 共享专家：除 Qwen3.8-27B 稠密版外全部 MoE，且都带 1~2 个共享专家 + sigmoid/softmax 路由 + 负载均衡设计（aux loss / 分组 / hash）。
  • ✅ KV 缓存压缩是主线：MLA 低秩潜变量（DSV3/GLM/Kimi/Dots）或线性注意力免缓存（Qwen/Kimi）或压缩+索引（DSV4）——目的都是降低长上下文内存。
  • ✅ 多 token 预测 MTP：DeepSeek、GLM、Qwen3.8 均带 1 层 MTP 头，提升推理吞吐与训练效率（Kimi-K3 未启用）。
  • ✅ 超长上下文：163K ~ 1M token 全覆盖。
  • ✅ 张量并行友好的 FP8/FP4 量化：DeepSeek 系与 Kimi 配置均带量化配置（fp8/fp4 专家）。

六、不同之处（差异化设计）

  • 🔀 注意力机制分四派：
      · MLA 派：DeepSeek-V3、GLM-5.2、Dots3、Kimi(部分) —— KV 先压到低秩潜变量再展开，缓存压缩比最高；
      · 线性注意力派：Qwen3.8、Kimi-K3 —— Gated DeltaNet/KDA，O(1) 状态递推，彻底不存 KV；
      · 稀疏/压缩派：DeepSeek-V4、GLM、Dots —— 索引器先挑 top-k 键再做注意力，复杂度随 top-k 而非序列长；
      · 滑动窗口派：Dots3、DeepSeek-V4、Mistral —— 只看最近 W 个 token，近似线性复杂度，配周期性全注意力层做跨窗中继。
  • 🔀 线性层与全注意力层比例不同：Qwen 3:1 固定循环；Kimi 66:24 约 2.75:1；Dots 全层仅 2 full + 滑动窗口；GLM 4 层一 full。
  • 🔀 MoE 规模悬殊：Kimi 896 专家 top-16（最宽）；DeepSeek V3 分组路由（8 组挑 4 组）保证均衡；V4 用 Hash Router + fp4 专家。
  • 🔀 残差连接风格：DeepSeek-V4 的 Hyper-Connection（3 流残差交互）、Kimi 的 attn 残差块（res_block 12 累积）、其余标准 pre-norm 残差。
  • 🔀 多模态范围：Qwen3.8-27B 视觉；Kimi-K3 视觉；Dots3 视觉+音频；DeepSeek/GLM 纯文本。
  • 🔀 上下文策略：DSV3 用 YaRN 扩窗；DSV4 用 compress 专用 RoPE(θ=160k)+索引；Qwen 用 partial RoPE + 长训练。
  • 🔀 位置编码细节：Qwen 多模态用 mRoPE（多模态 3D 位置）；GLM 用 interleaved RoPE；V4 双 RoPE（main/compress）。

八、四大 Token-Mixer 机制详解（教程）

MLA 低秩潜变量注意力 · Gated DeltaNet 线性注意力 · 压缩+索引稀疏注意力 · 滑动窗口注意力 —— 四者的原理、公式、源码对照与取舍

8.1 · MLA：多头潜变量注意力（Multi-head Latent Attention）

DeepSeek-V2 提出 · DeepSeek-V3 / GLM-5.2 / Dots3 / Kimi(部分层) 采用

① 解决什么问题

标准 MHA / GQA 在推理时要把每个历史 token 的 K、V 完整缓存，显存随序列长度线性增长：序列 100 万 token、128 头 × 256 维时，仅 KV 缓存就达数百 GB。长上下文（128K~1M）下 KV 缓存是最大的显存瓶颈。

② 核心思想

KV 在所有头之间共享，且本身信息冗余 —— 可以先用一个小矩阵把它压成低秩潜向量 c（例如 512 维），缓存时只存这个潜向量（外加一小段 RoPE 旋转的 krot），等真正要做注意力时再用另一个矩阵把它展开回多头 K、V。

// 压缩（缓存前，每 token 只存两个小张量）
c_KV = WDKV · h   // 潜向量，kv_lora_rank=512 维，所有头共享
krot = WKR · h      // 只带 RoPE 的键片段，qk_rope_head_dim=64 维

// 展开（计算注意力前，恢复多头 K/V）
[knope | v] = WUKV · c_KV  // 每头: qk_nope_head_dim + v_head_dim
k = [knope | RoPE(krot)]     // 键 = 无位置部分 + 旋转部分

③ 缓存压缩比

以 DeepSeek-V3 为例：传统 GQA 需缓存 n_kv_heads × (qk_nope + v_head) 维，而 MLA 只需 kv_lora_rank + qk_rope_head_dim = 512 + 64 = 576 维。展开后的键值维度为 128 × (128+128) = 32768 维 —— 缓存量约为展开值的 1/57，官方称较 MHA 压缩约 93%。

④ 源码对照（DeepseekV3Attention）

class DeepseekV3Attention: # —— Q 侧降秩升维 —— q_a_proj = Linear(hidden, q_lora_rank=1536) # 先压 q_a_layernorm = RMSNorm(q_lora_rank) q_b_proj = Linear(q_lora_rank, n_heads*qk_head_dim) # 再升回多头 # —— KV 侧压缩 + 展开 —— kv_a_proj_with_mqa = Linear(hidden, kv_lora_rank + qk_rope_head_dim) kv_a_layernorm = RMSNorm(kv_lora_rank) kv_b_proj = Linear(kv_lora_rank, n_heads*(qk_nope_head_dim+v_head_dim)) # forward：压缩 → 缓存 → 展开 → 普通 attention compressed_kv = kv_a_proj_with_mqa(h) # [B,1,S,576] 只缓存这个 kv_nope, k_rot = split(compressed_kv, 512, 64) kv_nope = kv_a_layernorm(kv_nope) k, v = expand_kv(kv_nope, k_rot) # 展开成多头 KV attn = attention(q, k, v)

8.2 · 线性注意力：Gated DeltaNet / KDA

Linear Attention → Delta Rule → Gated DeltaNet 演进 · Qwen3.8（GatedDeltaNet）与 Kimi-K3（KDA）采用

① 解决什么问题

注意力的 softmax(QKᵀ) 是非线性运算，无法拆成可递推的形式，所以必须把历史 K/V 全部缓存。线性注意力换一条路：不再保存 KV，而是维护一个固定大小的"记忆状态矩阵 S"，每读一个 token 就把信息写进状态，输出时用查询从状态里读取 —— 内存 O(1)、不随序列增长，天然支持无限长上下文。

② 三代演化

第 1 代 · Linear Transformer（2020）：等权累加，无遗忘，容量很快饱和
St = St-1 + kt · vtT    ot = qtT · St

第 2 代 · Delta Rule（2021）：按"预测误差"更新，像 Widrow-Hoff 学习规则
St = St-1 + βt · (vt − St-1·ktT) · ktT

第 3 代 · Gated DeltaNet（2024）：加入遗忘门 g 与写入门 β，可"选择性遗忘"
St = gt·St-1 + βt·(vt − St-1·ktT)·ktT  ot = qtT·St

其中遗忘门 g = −exp(A_log)·softplus(a + dt_bias) ∈ (0,1)（借自 Mamba 的连续时间离散化），写入门 β = sigmoid(b)。记忆状态 S 大小固定（每头 head_dim × head_dim），训练时用 chunk 并行（把序列切成块分块递推），推理时用 recurrent 模式（单步 O(1)）。

③ 源码对照（Qwen3_5MoeGatedDeltaNet）

class Qwen3_5MoeGatedDeltaNet: # —— 输入投影：QKV / 输出门 z / 写入门 b / 遗忘门 a —— in_proj_qkv = Linear(hidden, key_dim*2 + value_dim) # q,k,v 一次投影 in_proj_z = Linear(hidden, value_dim) # 输出乘性门控 in_proj_b = Linear(hidden, n_v_heads) # β = sigmoid(b) in_proj_a = Linear(hidden, n_v_heads) # 遗忘门控制 # —— 短卷积（Mamba 式局部混合） + 门控 Delta Rule 内核 —— conv1d = Conv1d(conv_dim, conv_dim, kernel=4, groups=conv_dim) # depthwise o, state = torch_chunk_gated_delta_rule(q, k, v, g, beta, A_log, dt_bias, use_qk_l2norm=True) # 训练: chunk 并行 o, state = torch_recurrent_gated_delta_rule(...) # 推理: 单步递推 # —— 门控 RMSNorm 输出 —— out = RMSNormGated(o, z) # norm(o) * sigmoid(z) 之类 out = out_proj(out)

④ Kimi-K3 KDA 与 Qwen 的差异

  • 投影方式：KDA 用独立的 q_proj / k_proj / v_proj，且每个通道各自接一个短卷积（q_conv1d / k_conv1d / v_conv1d）；Qwen 是 QKV 合一批 + 单一 conv。
  • 门控：KDA 用两段式 f_a_proj→f_b_proj 生成 g，另有 g_a_proj→g_b_proj（use_full_rank_gate 可选）；Qwen 是 in_proj_a 直出。
  • 输出：KDA 用 FusedRMSNormGated(activation='sigmoid')；Qwen 用 RMSNormGated(z)。
  • 安全门：KDA 带 gate_lower_bound=-5.0，防止遗忘门过小导致状态死掉。

⑤ 为什么还要保留 1/4 全注意力？

线性注意力是"有损压缩记忆"：它对需要精确召回的任务（复制、检索、代码中的符号对应）能力弱于精确注意力。所以 Qwen3.8 与 Kimi-K3 都采用混合布局（linear×3 + full×1 循环）——用大部分线性层换效率，保留少量全注意力层做"硬检索"兜底。这是当前业界平衡效率与质量的主流解。

✅ 优点① 推理内存 O(1) 恒定，任意长上下文不涨显存；② 解码每步 O(1) 计算，吞吐极高；③ 训练可用 chunk 并行，不完全牺牲并行度。
❌ 缺点① 记忆有损：状态容量有限，长程精确召回弱；② Delta Rule 状态在数值上更敏感，需 q/k L2 归一化、门控下界等"维稳"手段；③ 短卷积与递推使 batch 内 padding 处理更复杂。

8.3 · 压缩 + 索引稀疏注意力（HCA / CSA / DSA）

DeepSeek-V4（HCA+CSA+Lightning Indexer）· GLM-5.2（DSA 索引器）· Dots3（索引器）

① 解决什么问题

MLA 省了内存但注意力仍是 O(seq²)；线性注意力省了内存又省计算，但有损。压缩+索引想两头都要：保留"精确的 softmax 注意力"，但不让 query 看全部键——先压缩历史，再用一个轻量索引器为每个 query 挑出 top-k 个最重要的压缩块，只对它们做注意力。复杂度从 O(seq²) 降到 O(seq × top-k)。

② 三阶段流水线

历史 token 流 h₁ h₂ h₃ h₄ | h₅ h₆ h₇ h₈ | h₉ ... │ ① 压缩 Compress（每 m 个 token 压成 1 个压缩块） ▼ 压缩 KV 块 C₁ C₂ C₃ ... （含自身 RoPE，θ=160k 专用） │ ② 索引 Index（Indexer 打分，挑 top-k） ▼ query t ──► [C₅ C₂ C₉] ← top-k 候选块（其余 -inf 屏蔽） │ ③ 稀疏注意力 Sparse Attend（只算这 k 个块） ▼ 输出 o_t

③ 压缩器细节（DeepSeek-V4）

HCA · 重度压缩（compress_rate=128）：
Ci = RMSNorm( Σj∈窗口 softmax(Zj + Bj) · Cj )  // softmax 门控加权和
CSA · 细粒度压缩（compress_rate=4）：
每个 token 产生两个流 Ca（贡献给下一个窗口）、Cb（贡献给当前窗口）
压缩块 = 窗口 w-1 的 Ca 段 ∪ 窗口 w 的 Cb 段（宽度 2m，步长 m）// 重叠布局

压缩块的位置编码取窗口起点 i × compress_rate + first_window_position，使用独立的 compress_rope_theta=160000 旋转，保证跨调用拼接时因果性正确。HCA 提供"极长历史"的粗粒度记忆，CSA 提供中近距离的细粒度记忆，两者与滑动窗口（128）拼接后一起参与注意力。

④ 索引器（Lightning Indexer / DSA Indexer）

打分函数：先按头计算 ReLU 相似度，再按头加权求和
scoret,s = Σh wt,h · ReLU( qt,h · KIComps )
然后每 query 取 top-k： indices = topk(score, k=index_topk)
因果约束：指向未来窗口的候选被替换为 -1 哨兵（无效）
  • DeepSeek-V4：索引器自带一个小号压缩器（index_head_dim=128），64 头，top-k = 512（Flash）/ 1024（Pro）。
  • GLM-5.2：32 头 × 128 维，top-2048；跨层共享——indexer_types 每 4 层 1 个 full（自算 top-k），其余 shared 层直接复用前一 full 层的索引结果，省 3/4 索引器计算。
  • Dots3：64 头 × 128 维，top-2048，配合滑动窗口 513 使用。

⑤ 源码对照（DeepseekV4CSACompressor + Indexer）

class DeepseekV4CSACompressor: # 每 4 token 压 1 kv_proj = Linear(hidden, 2*head_dim) # 双流 Ca/Cb gate_proj= Linear(hidden, 2*head_dim) # softmax 门控 position_bias = Parameter(rate, 2*head_dim) kv_norm = RMSNorm(head_dim); rotary_emb = DeepseekV4RotaryEmbedding(θ=160k) indexer = DeepseekV4Indexer(config) # 内嵌 Lightning Indexer class DeepseekV4Indexer: kv_proj = Linear(hidden, 2*index_head_dim) # 小号压缩器 q_b_proj= Linear(q_lora_rank, n_heads*index_head_dim) scorer = IndexerScorer(weights_proj) # Σ w·ReLU(q·k) # forward: 压缩 → scorer 打分 → topk → 因果哨兵 -1 top_k_indices = index_scores.topk(index_topk).indices # Attention.forward 最终： kv = cat([sliding_kv, compressed_kv], dim=2) # 滑动窗口 KV + 压缩块 block_bias = 只在 top-k 索引处置 0，其余 -inf # 屏蔽未选中的块 attn_output = attention(q, kv, kv, mask + block_bias)
✅ 优点① 保留精确 softmax 注意力，无有损记忆；② 计算 O(seq×topk)，长上下文大幅提速；③ 压缩块同时降内存（约 m 倍）；④ 索引器可跨层共享（GLM）进一步省算。
❌ 缺点① 索引器若选错 top-k 会漏掉重要信息（recall 风险）；② 需要压缩器+索引器两套额外参数与两套 cache；③ 实现复杂度最高（Ca/Cb 重叠、跨调用状态、因果哨兵）；④ 索引打分本身也要维护 KV。

8.4 · 滑动窗口注意力（Sliding Window Attention）

Dots3-Note（窗口 513）· DeepSeek-V4（窗口 128）· Mistral / Longformer 同源思想

① 解决什么问题

全注意力每个 query 都要和全部历史做点积，计算与显存都是 O(seq²)，长序列下开销随长度二次方膨胀。但研究发现：注意力权重其实高度局部化——与 query 距离近的 token 贡献了绝大部分注意力分数，真正需要远距离信息的位置只是少数（可交给少量全注意力层兜底）。滑动窗口的思路因此很直接：每个 query 只能看它前面最近 W 个 token，把复杂度从 O(seq²) 压到 O(seq × W)。

② 核心思想：带状掩码（Band Mask）

// 因果掩码之上再加一层"窗口截断"：只允许 attend 到 [i−W, i] 区间
mask[i][j] = −∞  若  j < i − W  （窗口外全部屏蔽）
// 效果：QK^T 矩阵只剩一条"带状"区域非 −∞
  j→  0  1  2  3  4  5  6  7
i=4   ✗ ✗ ✗ ✗ ✓ ✓ ✓ ✗  // ✓=attend（窗口 W=3 时只到 j=4..7 之外屏蔽…示意）
// 滑动窗口 KV 缓存：只保留最近 W 个 KV，旧 token 直接被丢弃

③ 源码对照（Dots1Attention）

class Dots1Attention: # 层类型为 sliding_attention 时启用窗口，否则为 None（全注意力） self.sliding_window = config.sliding_window \ if self.layer_type == "sliding_attention" else None # forward 中把窗口传给注意力内核，由内核在 mask 里做截断 attn_output, _ = attention_interface( self, q, k, v, attention_mask, sliding_window=self.sliding_window, # ← 窗口生效处 **kwargs)

Dots3-Note 的配置里 sliding_window_size=513，且它的滑动层使用独立一套 swa_* MLA 参数（swa_q_lora 1024、swa_kv_lora 1024、swa 头 64、θ=50000），说明滑动层与全注意力层是"两套可独立调参的 MLA"。DeepSeek-V4 的 sliding 层窗口为 128，其 DeepseekV4HCACache 继承自 DynamicSlidingWindowLayer——缓存本身就是滑动窗口结构，旧 KV 出窗口即释放。

④ 混合使用：窗口层 + 全注意力层

Dots3-Note 46 层： F F S S S | F F S S S | ... （每 5 层 2 个全 + 3 个滑动，窗口 513） DeepSeek-V4 43/61 层：S C C C ...（sliding 窗口 128 打底，CSA/HCA 压缩层负责远距离） Mistral 32 层： F S S S S S S S | F S S ... （每 8 层 1 个全注意力，窗口 4096）

纯窗口注意力有一个已知弱点：信息跨窗口无法传递（第 100 个 token 看 513 窗口内的内容，窗口外的东西被完全屏蔽）。所以工业界从不单独使用滑动窗口，而是周期性插入全注意力层做"信息中继"——窗口层负责局部精细建模，全注意力层负责把远端信息搬进窗口。Dots3 是 5 层一循环、Mistral 是 8 层一循环，思路一致。

✅ 优点① 计算/内存 O(seq×W) 近似线性，长序列友好；② 实现极简——只需在 mask 里加一条带状约束 + 窗口 KV 缓存；③ 局部建模能力强（N-gram 级精细上下文、位置敏感）；④ 与 MLA/压缩注意力正交，可自由叠加。
❌ 缺点① 窗口外信息完全不可见，跨窗口长程依赖丢失；② 单独使用效果差，必须配全注意力/压缩层做中继；③ 窗口 W 是超参数，太小伤长程能力、太大失去省算意义；④ 训练与推理需保持同一窗口语义（chunk 边界处理要小心）。

九、各模型数据流与张量尺寸（输入 → 输出全链路）

符号约定：B=batch，S=序列长度，H=hidden_size，V=vocab_size。所有模型均为 decoder-only，共用同一宏观骨架，差异集中在「Token Mixer」与「FFN/MoE」两步。
